# 🌈 What is CPU and Memory in Kubernetes?
 * When you deploy applications in Kubernetes, you define `CPU` and `Memory resources` for containers.

## 🖥️ CPU (Processing Power)
 * CPU is the amount of processing power your application can use.

### In Kubernetes

```yaml
resources:
  requests:
    cpu: 100m
```
 * **100m means 100 millicores = 0.1 CPU core**

### Common Values
| 🚀 CPU Value | 📖 Meaning |
|-------------|------------|
| 100m | 0.1 CPU core |
| 250m | 0.25 CPU core |
| 500m | 0.5 CPU core |
| 1000m | 1 CPU core |
| 2000m | 2 CPU cores |

### Example
 * If an EC2 node has : 4 vCPU
 * and your pod requests:
  ```yaml
  cpu: 500m
  ```
 * then the pod gets: `0.5 CPU core`

---

## 🧠 Memory (RAM)
 * Memory is the `RAM` used to` store data` while the application is running.

### In Kubernetes
```yaml
resources:
  requests:
    memory: 256Mi
```

### Common Values
| 🧠 Memory Value | 📖 Meaning |
|----------------|------------|
| 128Mi | 128 MB |
| 256Mi | 256 MB |
| 512Mi | 512 MB |
| 1Gi | 1024 MB (1 GB) |
| 2Gi | 2048 MB (2 GB) |

---

# 🎯 Requests vs Limits
```yaml
resources:
  requests:             #Scheduler uses requests to decide where to place the pod.
    cpu: 200m
    memory: 256Mi

  limits:
    cpu: 500m
    memory: 512Mi
```
| 🧩 **Resource Setting** | 🎯 **Purpose**       | 📖 **Description**                            | 
| ----------------------- | -------------------- | ----------------------------------------------- |
| ✅ **Requests**          | Minimum resources Kubernetes guarantees| Minimum CPU and Memory reserved for a container | 
| 🚧 **Limits**           | Maximum Resources    | Maximum CPU and Memory a container can consume  | 


---

# ⚠️ What Happens When Limits Are Exceeded?

## 🖥️ CPU Limit Exceeded
```yaml
limits:
  cpu: 500m
```
* If the container tries to use:
```text
800m CPU
```
 * Kubernetes throttles CPU usage.
 * ✅ The pod keeps running but becomes slower.

---

## 🧠 Memory Limit Exceeded
```yaml
limits:
  memory: 512Mi
```
 * If the application uses:
```text
700Mi RAM
```
 * The container is killed with:
```text
OOMKilled (Out Of Memory)
```
 and restarted.

---

# 🎤 Easy Interview Answer

 * ✅ CPU = Processing power used to execute application code.
 * ✅ Memory = RAM used to store application data while running.
 * ✅ CPU overuse → Container is throttled. ( its CPU usage has been `restricted` by the system )
 * ✅ Memory overuse → Container is `OOMKilled` and `restarted`.
 * ✅ HPA commonly `scales pods` based on `CPU` or `Memory` utilization.
