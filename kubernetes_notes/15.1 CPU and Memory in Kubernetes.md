# 🌈 What is CPU and Memory in Kubernetes?
When you deploy applications in Kubernetes, you define CPU and Memory resources for containers.

---

## 🖥️ CPU (Processing Power)

CPU is the amount of processing power your application can use.

> Think of CPU as the speed of the worker doing tasks.

### Examples
- Serving web requests
- Processing API calls
- Running calculations
- Executing application code

### In Kubernetes

```yaml
resources:
  requests:
    cpu: 100m
```

**100m means 100 millicores = 0.1 CPU core**

### Common Values

| 🚀 CPU Value | 📖 Meaning |
|-------------|------------|
| 100m | 0.1 CPU core |
| 250m | 0.25 CPU core |
| 500m | 0.5 CPU core |
| 1000m | 1 CPU core |
| 2000m | 2 CPU cores |

### Example

If an EC2 node has:

- 4 vCPU

and your pod requests:

```yaml
cpu: 500m
```

then the pod gets:

- 0.5 CPU core

---

## 🧠 Memory (RAM)

Memory is the RAM used to store data while the application is running.

> Think of memory as the workspace or desk where the worker keeps files.

### Examples

- Java heap memory
- Application cache
- Variables and objects
- Loaded libraries

### In Kubernetes

```yaml
resources:
  requests:
    memory: 256Mi
```

### Common Values

| 🧠 Memory Value | 📖 Meaning |
|----------------|------------|
| 128Mi | 128 MB |
| 256Mi | 256 MB |
| 512Mi | 512 MB |
| 1Gi | 1024 MB (1 GB) |
| 2Gi | 2048 MB (2 GB) |

---

# 🎯 Requests vs Limits

## ✅ Requests

Minimum resources Kubernetes guarantees.

```yaml
requests:
  cpu: 200m
  memory: 256Mi
```

Scheduler uses requests to decide where to place the pod.

## 🚧 Limits

Maximum resources the container can consume.

```yaml
limits:
  cpu: 500m
  memory: 512Mi
```

---

# ⚠️ What Happens When Limits Are Exceeded?

## 🖥️ CPU Limit Exceeded

```yaml
limits:
  cpu: 500m
```

If the container tries to use:

```text
800m CPU
```

Kubernetes throttles CPU usage.

✅ The pod keeps running but becomes slower.

---

## 🧠 Memory Limit Exceeded

```yaml
limits:
  memory: 512Mi
```

If the application uses:

```text
700Mi RAM
```

The container is killed with:

```text
OOMKilled (Out Of Memory)
```

and restarted.

---

# ☁️ Real Example in EKS

```yaml
resources:
  requests:
    cpu: 200m
    memory: 256Mi

  limits:
    cpu: 500m
    memory: 512Mi
```

### Meaning

🟢 Minimum Guaranteed:

- CPU = 0.2 Core
- Memory = 256 MB

🔴 Maximum Allowed:

- CPU = 0.5 Core
- Memory = 512 MB

---

# 📈 How HPA Uses CPU

Suppose:

```yaml
requests:
  cpu: 100m
```

HPA target:

```yaml
averageUtilization: 50
```

50% of 100m = 50m

If actual usage becomes:

```text
80m
```

CPU utilization:

```text
80 / 100 × 100 = 80%
```

HPA sees:

```text
80% > 50%
```

and creates more pods.

---

# 🎤 Easy Interview Answer

✅ CPU = Processing power used to execute application code.

✅ Memory = RAM used to store application data while running.

✅ CPU overuse → Container is throttled. ( its CPU usage has been `restricted` by the system )

✅ Memory overuse → Container is OOMKilled and restarted.

✅ HPA commonly scales pods based on CPU or Memory utilization.
